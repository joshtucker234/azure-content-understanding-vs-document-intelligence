# Content Understanding vs Document Intelligence: invoices and video

A hands-on project. You extract structured data from invoices and a short video using **Azure AI Content Understanding**
and **Azure AI Document Intelligence**, run them side by side against known answers, and learn where they agree, where they
fail, and what each costs. Everything is keyless (Microsoft Entra identities and RBAC only), and a web UI lets
you inspect every source and every result.

I built it as a hands-on way to learn Microsoft Foundry's Content Understanding and Document Intelligence, and you can follow it
yourself to learn the same tools by testing them.

| | |
|---|---|
| **Time** | About 1-2 hours hands-on (our estimate). Every call returns in seconds to about a minute, so there is nothing slow to wait for |
| **Cost** | Expected well **under $2** at list prices (see [Cost](#cost-and-cleanup)). We did not check the actual bill. **Delete the resource group when done** |
| **You need** | An Azure subscription where you can create resources and assign RBAC roles (Owner, or Contributor plus User Access Administrator), Python 3.11+, Azure CLI, Git Bash or any POSIX shell |
| **Skills** | Content Understanding analyzers and field schemas, prebuilt vs custom analyzers, Document Intelligence prebuilt models, video analysis, standard vs pro mode, confidence scores and human review, keyless auth |

## What it uses

| Piece | Technology |
|---|---|
| Resource | One Microsoft Foundry resource (`AIServices`). It serves Content Understanding **and** Document Intelligence. No Search, no Storage |
| Models | `gpt-4.1`, `gpt-4.1-mini`, `text-embedding-3-large` (GlobalStandard). Content Understanding calls them for generated fields and prebuilt analyzers |
| Content Understanding | API `2025-11-01`: a custom invoice analyzer, the prebuilt `prebuilt-invoice`, `prebuilt-videoSearch`, and a custom video analyzer |
| Document Intelligence | API `2024-11-30`: the prebuilt `prebuilt-invoice` model |
| Security | `DefaultAzureCredential` everywhere (Azure CLI login), RBAC roles, no keys |
| App | Plain Python (`requests` + `azure-identity`) for the calls; Streamlit UI with a dark theme and an in-app PDF viewer |
| Test data | Synthetic invoices and a video generated by scripts, plus two real public invoices (Apache 2.0) downloaded on demand. Ground truth for all of them is in the repo |

## The steps

Each step maps to a line of the lab and to a script. Details and commands are in [docs/REPLICATE.md](docs/REPLICATE.md).

| # | What you do | What it teaches | Script |
|---|---|---|---|
| 1 | Create a custom Content Understanding analyzer that returns invoice fields as JSON | Analyzers, field schemas, `extract` vs `generate` vs `classify` | `app/01_cu_invoice_analyzer.py` |
| 2 | Run the same invoices through Document Intelligence | Prebuilt models, a fixed output shape | `app/02_di_invoice.py` |
| 3 | Compare field accuracy and output shape between the two | Normalizing different outputs, scoring against ground truth, why confidence is not correctness | `app/06_cu_prebuilt_invoice.py`, `app/03_compare.py`, `app/07_run_harder.py` |
| 4 | Create a video analyzer and extract segments and descriptions | Prebuilt vs custom video analyzers, segments for search vs fields for extraction | `app/04_video_analyzer.py` |
| 5 | Try single-task mode versus pro mode and note differences | Standard vs pro mode, and what happens when a preview API is retired | `app/05_standard_vs_pro.py` |
| + | Add a confidence threshold that routes low-confidence fields to a human review step | Review queues, and how many errors a threshold misses | `app/03_compare.py`, UI **Scorecard** tab |

Step 3 goes further than the lab text: we added Content Understanding's own prebuilt invoice analyzer for a like-for-like comparison with
Document Intelligence's prebuilt model, and a **harder set** of five documents (three synthetic and two real).

## Results we got (use these to sanity-check your build)

### Easy set: three clean synthetic invoices

All three analyzers got **every scored field and every line amount right** (30/30 header fields, 10/10 line amounts each). Accuracy does
not separate them on clean documents. See [results/COMPARE.md](results/COMPARE.md).

### Harder set: 3 synthetic + 2 real invoices

A 2-page invoice with 26 lines; a low-resolution fax scanned sideways; an invoice with discounts, freight, a credit, a partial payment, a stamp
over the totals and the currency only stated in words; and two real public invoices (one image-only with comma decimals, one Spanish and covered in
handwriting and highlighter). Full tables in [results/COMPARE_HARDER.md](results/COMPARE_HARDER.md).

| Analyzer | Header fields correct | Line amounts found | Median time per document | Est. cost (6 pages) |
|---|---|---|---|---|
| Content Understanding, custom analyzer | 49/50 | 42/43 | 13 s | $0.14 |
| Content Understanding, `prebuilt-invoice` | 49/50 | 42/43 | 31 s | $0.21 |
| Document Intelligence, `prebuilt-invoice` | 47/50 | 43/43 | about 8 s | $0.06 |

What to take from it:

- **Still close to a tie.** The only misses were on the degraded fax and the scribbled real invoice.
- **The tools fail differently.** On the fax, both Content Understanding analyzers dropped the leading `I` of `INI-60417`, lost two quantities and read
  `79.80` as `79`. Document Intelligence got every line amount right but read the subtotal as `12,413.40` instead of `1,413.40`, at 94% confidence.
- **Confidence did not catch the biggest error.** At a 0.80 review threshold Document Intelligence's wrong subtotal and wrong invoice ID would not be
  flagged. A simple check (do the lines add up to the subtotal?) would have caught the subtotal.
- **Handwriting and stamps.** On the scribbled invoice, Content Understanding was clean. Document Intelligence put an `ATTN:` contact line into the customer
  name (a judgment call: arguably not part of the name, and we scored it wrong) and returned `nº2` as the invoice ID.
- **The tricky layout was easy for all three.** Multi-page totals, three dates, discounts, freight, a stamp over the totals, invoice total vs balance
  payable, and AUD stated only in the footer were all handled correctly.
- **No analyzer invented a value.** On the invoice with no tax and no PO number, none made one up.
- **Same document, different reading.** On the real dress invoice, Content Understanding returned the **net** line amounts and Document Intelligence the
  **gross** ones. Both are defensible, nothing flags it, and your downstream system has to know which it expects.
- **Be skeptical of small samples.** Eight invoices, one run each. Two files are public samples the models may have seen. These are observations, not a
  benchmark. Real-world messy invoices will separate the tools more than any synthetic file.

### The two prebuilt invoice analyzers, measured on the easy set

| | Content Understanding `prebuilt-invoice` | Document Intelligence `prebuilt-invoice` |
|---|---|---|
| Accuracy | 30/30 | 30/30 |
| Fields returned per invoice | 31 (fixed schema) | 14 to 16 |
| Average confidence on correct values | 0.62 | 0.87 |
| Model tokens used per page | about 9,500 gpt-4.1 input, 860 output, 400 embedding | none reported |
| Money fields | nested `Amount` + `CurrencyCode` object | one flat amount |
| Field names | `PONumber`, `SubtotalAmount`, `TotalTaxAmount`, `TotalAmount` | `PurchaseOrder`, `SubTotal`, `TotalTax`, `InvoiceTotal` |

Content Understanding's prebuilt analyzer is **language-model based** (its responses report gpt-4.1 token usage on every page), so it uses your deployment's
capacity and costs more per page. The two use different field names and money shapes, so switching means rewriting your parser. Never compare confidence
numbers across tools.

### Video

- **`prebuilt-videoSearch`** split the 28-second video into 4 segments, one per slide, each with a generated description. Those descriptions are general:
  they captured only **2 of the 9** planted facts (speed limit, dock number, spill extension and others were missing).
- **A custom analyzer** returned one segment for the whole video with the fields we defined, and captured **all 9** facts.
- Use segments for **search and RAG chunks**; use a custom schema for **structured extraction**. The demo video is silent, so audio transcription was not tested.

### Standard vs pro mode

Pro mode (multi-step reasoning, several input documents, an external knowledge base; documents only; no confidence scores) existed only in
`2025-05-01-preview`. That API is **retired** (`410 Gone`) and the current API is standard mode only, so **you cannot run pro mode today**. The script records
that and runs reasoning-style `generate` fields in standard mode instead. Learn pro mode as a concept for the exam.

## Quick start

```bash
git clone https://github.com/joshtucker234/azure-content-understanding-vs-document-intelligence && cd azure-content-understanding-vs-document-intelligence
cp scripts/00-env.sh.example scripts/00-env.sh      # edit: subscription, your email, a fixed SUF
source scripts/00-env.sh
az login && bash scripts/01-provision.sh            # Foundry resource, 3 model deployments, roles, Content Understanding defaults
bash scripts/02-fetch-real-samples.sh               # the two real public invoices (optional but recommended)
cd app && python -m venv .venv && . .venv/Scripts/activate    # Linux/macOS: . .venv/bin/activate
pip install -r requirements.txt
python 01_cu_invoice_analyzer.py && python 02_di_invoice.py && python 06_cu_prebuilt_invoice.py
python 03_compare.py 0.80 easy
python 07_run_harder.py && python 03_compare.py 0.80 harder
python 04_video_analyzer.py && python 05_standard_vs_pro.py
streamlit run ui.py --server.address localhost
```

**No Azure yet?** The UI works straight after cloning, because our results are committed: `cd app && pip install -r requirements.txt && streamlit run ui.py --server.address localhost`.

Read [docs/REPLICATE.md](docs/REPLICATE.md) before running anything: it explains what each step does and what to check.

## Security notes

- **No secrets in this repo and none are needed.** Everything authenticates with `DefaultAzureCredential`. There are no keys to turn off because none are used.
- `scripts/00-env.sh` holds your subscription ID and email. It is git-ignored. Do not commit it.
- All invoices and the video are fabricated or generated. The two real invoices are public Apache 2.0 samples with fake names, downloaded by you and not stored in this repo.
  In our saved results, a third party's contact name, email and phone from one sample were redacted, and the per-call operation IDs removed.
- Do not put customer or confidential documents in this lab. Use the pattern, not the data.
- The UI makes no Azure calls. Run it with `--server.address localhost`, because the scripts run with your identity.

## Cost and cleanup

List-price estimates (Azure retail price API, East US 2). **Not billed amounts. We did not check Cost Management.**

| Item | Approx. cost |
|---|---|
| Document Intelligence `prebuilt-invoice` | $10 per 1,000 pages, about **$0.01 per page**, no model tokens |
| Content Understanding `prebuilt-invoice` | about **$0.03 per page**: $5 per 1,000 pages for extraction (a nearby meter is $7.50), plus gpt-4.1 at $2 / $8 per million input / output tokens and embeddings at $0.13 per million. Tokens are billed through your model deployment. The ~$0.03 uses the token counts in our own responses |
| Content Understanding video | about $1 per hour of video plus tokens. Our 28-second clip cost a few cents per run |
| The whole lab | We expect well under $2, including the harder set |

Content Understanding costs about 3 times as much per invoice page as Document Intelligence on these files. It earns that where you need your own
schema, generated fields, or video and audio. For standard invoices at volume, Document Intelligence returned the same answers here for less.

**When you are done, delete the resource group:** `bash scripts/99-cleanup.sh`. Azure keeps a deleted AI account in soft delete for a few days at no charge.
